# Codex review hooks

A global, context-aware review gate for Codex. It fingerprints the exact Git state for a session, routes changed repositories through an independent architecture decision when needed, and requires a source-grounded conclusion before Codex finishes.

## How it works

```text
SessionStart -> record immutable repository baseline
     Stop -> unchanged or outside Git ----------------------> finish
          -> exact Salesforce remote exemption -------------> conclusion_writer -> finish
          -> obvious engineering change -> architecture_reviewer -> conclusion_writer -> finish
          -> ambiguous/non-engineering change -> architecture_scope_classifier
                                                   -> not required -> conclusion_writer -> finish
                                                   -> required -> architecture_reviewer -> conclusion_writer -> finish
```

The fingerprint covers HEAD, the index, tracked worktree changes, non-ignored untracked files, and initialized submodules. For files already dirty when a session starts, the gate stores protected baseline material under the worktree's Git directory and generates a session-only delta artifact so reviewers do not attribute earlier work to the current session.

`SubagentStop` records only strict outputs from the three configured roles. `Stop` also has transcript-evidence recovery for compatible Codex child rollouts. Any edit after classification, review, or conclusion changes the fingerprint and invalidates that evidence.

## Included files

- `hooks.json` registers the global `SessionStart`, `SubagentStop`, and `Stop` handlers.
- `hooks/` contains the standard-library-only Python implementation and its tests.
- `agents/` defines the read-only classifier, architecture reviewer, and conclusion writer.
- `AGENTS.md` tells the parent Codex agent how to obey the gate's routing instructions.

Generated bytecode, transcripts, backups, trust hashes, `config.toml`, and per-session state are intentionally excluded because they are machine-specific.

## Requirements

- Codex with lifecycle hooks and custom subagent profiles.
- Git.
- `/usr/bin/python3` with Python 3.11 or newer. The hooks use only the Python standard library.
- A Unix-like shell for the commands in `hooks.json`.

## Install

Clone the repository:

```sh
git clone https://github.com/coalio/codex-hooks.git
cd codex-hooks
```

For a new installation, run:

```sh
./install.sh
```

The installer writes to `${CODEX_HOME:-$HOME/.codex}`. It refuses to overwrite different files. To replace an existing installation, first review the diff, then run:

```sh
./install.sh --force
```

`--force` backs up every replaced file beneath `$CODEX_HOME/backups/` before installing. If your existing `AGENTS.md` or `hooks.json` contains unrelated policy or hooks, merge the review-gate section and event handlers manually instead of replacing those files.

After installation:

1. Start Codex and open `/hooks`.
2. Review and trust the new hook definitions. Codex records trust against their exact hashes, so changed hooks remain disabled until trusted.
3. Start a fresh Codex session in the repository you want to work on. The fresh session is required so `SessionStart` can record the immutable baseline.

## Validate

Run the regression suite without creating bytecode:

```sh
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 -m unittest discover -s hooks/tests -p 'test_*.py' -v
```

Validate the configuration formats:

```sh
/usr/bin/python3 -m json.tool hooks.json >/dev/null
/usr/bin/python3 -c 'import pathlib, tomllib; [tomllib.loads(path.read_text()) for path in pathlib.Path("agents").glob("*.toml")]'
```

## Policy notes

The global guidance and reviewer profile enforce responsibility ownership as an
architectural requirement. Keep one cohesive service for an owner, or group its
independent capabilities under a common domain or provider namespace. A broad owner
service alongside independently implemented feature services for that owner fails
this rule. Review contracts and dependencies as well as names, including relevant
existing siblings. Apply the same ownership rule to shared CI quality checks while
preserving their coverage and strictness.

The policy cites Microsoft's Architectural principles, Design for evolution,
Identify microservice boundaries, and Use domain analysis to model microservices.
The global guidance and reviewer profile include all four reference links and their
applicable principles. Provider namespaces and shared CI configuration are local
conventions derived from that guidance, not folder layouts prescribed by Microsoft.
The reviewer receives the reference summaries directly and remains read-only.

The installed policy deterministically exempts only the repository whose initial and current normalized canonical remote is `github.com/GreysteelCompany/salesforce`. Work outside Git and sessions with no net repository change also skip model review. Change `EXEMPT_REMOTE` in `hooks/review_gate_common.py` and the matching language in `AGENTS.md` and the classifier profile only if you intentionally want a different exemption.

All three agents are read-only. The architecture reviewer may publish review comments only when the user explicitly authorizes that external write for an exact open pull request; the classifier and conclusion writer never publish.
